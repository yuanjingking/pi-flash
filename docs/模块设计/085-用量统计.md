# 085 用量统计

> 需求（2026-10-29 用户）：①会话最下方显示当前会话的 token 消耗与缓存数；
> ②每轮对话显示「当次」消耗；③一个可查看「每天 × 每个模型」消耗明细的页面。

## 1. 数据从哪来

| 界面 | 数据源 | 刷新时机 |
| --- | --- | --- |
| 会话底部累计条 | RPC `get_session_stats` → `runtime.stats`（`pi_link::protocol::SessionStats`） | 轮末 `refresh_state()`（`session/runtime/mod.rs`）后即为最新 |
| 每轮消耗行 | 该轮 `Msg.usage`（`session/messages/model.rs::UsageLine`）求和 | 渲染时现算（纯内存加法） |
| 用量统计页 | 扫 `~/.pi/agent/sessions/**/*.jsonl` 里 assistant 消息的 `message.usage` | 打开弹窗时后台线程重算（增量缓存，见 §3） |

口径统一：`input`/`output`/`cache_read`/`cache_write` 全取 pi 落盘的 usage 原值，
**不做估算**（`estimate.rs` 只服务未跑完的草稿会话，不参与统计）。
缓存数 = `cache_read + cache_write`（底部条/轮末行显示合计，统计页分列可查）。
缓存命中率 = `cache_read / (input + cache_write + cache_read)`，与
`SessionStats::cache_hit_rate()` 同式，避免两处口径打架。

费用：`usage.cost.total`（对象）或 `usage.cost`（数字）两种 pi 写法都认。

## 2. 三处界面

### 2.1 会话底部累计条（`crates/app/src/usage/footer.rs::session_footer`）

- 挂在 `session/input/area.rs::composer_wrap` 的 composer 包装层内、**绝对
  定位 `.bottom(px(2.))` 居中**：不占布局高度，胶囊位置一动不动。
- 文案 `↑输入 ↓输出 · 缓存 · $费用`（`usage.*` i18n 键 + `fmt_tokens` 紧凑格式）。
- 新会话页（hero）不渲染；`stats` 还没回来（无 RPC 会话 / 尚未跑过 agent）也不渲染。
- 点击 → `Chat::open_usage_stats`（底部条即统计页入口，省一个菜单项）。

### 2.2 每轮消耗行（`usage/footer.rs::turn_usage_line`）

- 插在 `session/messages/turn.rs::render_assistant_turn` 尽头、消息操作栏
  之前，**常显**（不随 hover 显影），`本次 ↑x ↓y · 缓存 z · $cost`。
- 数值 = 该轮全部 assistant 消息 usage 求和。历史决策曾是「只取末条」
  （pi-web omitUsage parity），本次按用户「当次消耗」语义推翻：一轮里可能
  有多次模型调用（工具循环），只取末条会漏账。

### 2.3 用量统计页（`usage/dialog.rs`，`Dialog::UsageStats`）

- 外壳 `ui::overlay::big_card`（设置弹窗同款 0.7×0.98 大卡），内容三段：
  - 顶部固定汇总条：Token 累计（+调用次数）/ 输入·输出 / 缓存（+命中率）/
    累计费用（+会话文件数）；
  - 搜索行（091-1）：日期 / 模型关键词过滤。输入框实体在
    `open_usage_stats` 懒建一次（`TextInput::new` 不需 Window），on_change
    镜像词到 `UsageUi::filter` + notify；过滤为 OR 口径（日期子串或模型
    子串，不区分大小写），过滤时汇总条重算、滚动位复位；「清除」一键复位；
  - 下方滚动区：表头（模型/输入/输出/缓存/费用/调用）+ 每日卡片（日期 +
    当日合计 + 该日每会话明细行）。**明细行可点击跳会话**（091-1）：行内
    显示会话文件名前缀 + 六列数值，点击 → 关弹窗 + `goto_usage_session`
    （`pool::open_session_detached` 唤醒会话 + `switch_to` 切注意力；
    cwd 解析池→项目组→工作区兜底同源，孤儿会话不开）。
- 单帧最多画 120 天（多出的以 `+N` 提示），避免几年历史把一帧拖垮。
- 状态在 `AuxUi::usage`（`UsageUi { stats, loading, scroll }`）：`scroll` 是
  `ScrollHandle`，必须跨帧复用（见 `docs/agents/gpui.md` 滚动血案）。

## 3. 扫描与缓存（`crates/pi-link/src/usage_stats.rs`）

- `scan(root, cache_path)`：遍历会话根下两层分组目录里的 `*.jsonl`，逐行
  粗筛（`"usage"` + `assistant` 子串）后才 JSON 解析，只认完整行。
- 分桶键 `(本地日期, provider, model, 会话文件)`；日期由条目 ISO 时间戳转
  `chrono::Local` 得到（用户看的是本地日，不是 UTC 日）。桶里另记
  `first_line_start`（该条 usage 首次出现的行首字节偏移）。
- **重复 entry 只计一次**：pi 同一消息可能落多条 usage entry，同一行首
  （或数值全同）的重复只留首条——既是消息本体（点击跳发言处），也不双倍
  计费；两条不同消息撞相同 usage 是合法的，各自不同行首照计。
- 聚合三层同源：`UsageDay.sessions`（日级会话明细，费用/token 降序）→
  `UsageRow.sessions`（该模型当日子集）→ 日/模型合计（只从明细累加一遍，
  防双倍）。
- 缓存文件 `<PF数据目录>/usage-stats.json`（`paths::usage_stats_cache_file`）：
  每文件记 `(mtime, size, 已解析字节数, 桶)`：
  - 指纹一致 → 直接复用；
  - 文件变长 → 从上次字节偏移续读（只追加新行）；
  - 变短 / 无记录 / `version` 不符 → 该文件全量重扫。
- 结果落盘走 `config::write_json`（原子替换），下次启动首开弹窗即秒开。
- `CACHE_VERSION` 变更 = 全量重扫，改分桶口径时必须 bump
  （v1→v2：桶补 file + first_line_start，明细跳会话依赖）。

## 4. 铁律落地

- 渲染热路径零 IO：弹窗打开先显示旧快照，`background_executor` 线程里扫盘，
  完成后 `cx.spawn` 回写 + `notify`。
- 连点入口不会叠线程（`UsageUi::loading` 守门）。
- UI 全部走规范令牌（`ui_size()` + 主题色 + `ui/kit` 组件），无手搓控件。

## 6. 已知边界

- 只统计**本机落盘**的会话；已删除的会话文件不计（扫的是现存文件）。
- 子代理会话文件若不在同一会话根下则不计；同根下会被计入（与「总消耗」语义一致）。
- 模型名取 `message.model`；老会话缺 provider 时聚合行只显示模型名。
